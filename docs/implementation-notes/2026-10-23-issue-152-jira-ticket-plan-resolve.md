## 自分で判断した事項（仕様外）

- closed がヒットしたときの plan の選択肢は「再オープンして更新 / 新規作成 / 中止」とした。resolve は 1 件 closed のとき手順 1 の既存クローズ判定で終了し、`/smart-issue-plan <キー>` を案内する
- semantic 検索で 0 件だった場合は不在の証明にせず、`gh issue list` で裏取りする
- 作成直前に `updated` を取り直し（U_pre）、U1 と差があれば書き戻しでも U1 を残す（計画作成中・レビューループ中の Jira 更新が書き戻しで隠れるのを防ぐ）
- 更新モードでは Jira コメントを再投稿しない（再投稿すると `updated` が進み、もう一度書き戻しが要るため）
- Jira 起点の判定は、タイトル接頭辞か本文冒頭の `> 元チケット:` 行で行い、`#N` 入力にも適用する
- キーの `_` を残す。`-wt` の名前上限 64 文字を超える場合は説明部分を先に短くする
- resolve の `context.md` には元チケット 1 行を加える。Jira の説明のうち受け入れ基準の部分だけは、2-J で取得できたときに「要件・受け入れ基準」欄へ写す（未確定事項 2 の解釈。当初は説明を一切入れない最小解釈だったが、設計レビューで QA が要約の数行しか照合できなくなる指摘を受けて修正）
- MCP 不在のまま貼り付けで続行した場合の要件基準行は `> 要件基準: 未取得（Atlassian MCP 不在のため要件はユーザー貼り付け）`（未確定事項 3。resolve は「読めない」として扱う）
- 未確定事項 1（フラグ明示時に承認ゲートなしで Jira の要件の要約が GitHub Issue に載る）は現行どおりのまま（README に注意書きを入れた）。Jira 起点で承認ゲートを常に残すかは、ユーザーの判断事項として残す
- CLAUDE.md に二重化 bullet を追加し、PR 本文テンプレート同期 bullet に Jira リンクの記載先は resolve 固有と補足した
