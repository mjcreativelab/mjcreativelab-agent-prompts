# human-facing-doc-writing

人間が読む文書を、読み手が短時間で「何が決まったか・何をすればよいか」をつかめる形で書く・書き直すスキル。生成 AI の書く文書にありがちな 4 つの癖（網羅と重要度の混同・結論が最後・定型見出しの穴埋め・自明な両論併記）を、文書の部品と順序を先に決めることで防ぐ。

## 使用例

```
# 会話で決めた設計を Design doc にする
/human-facing-doc-writing 会話で決めたキャッシュ方針を Design doc にして

# PR 本文を書く
/human-facing-doc-writing このブランチの PR 本文を書いて

# 既存の長い文書を書き直す（削る内容の一覧を確認してから上書きする）
/human-facing-doc-writing docs/design/payment.md を読みやすく書き直して
```

スラッシュコマンドで呼ばなくても、「設計書を書いて」「報告書にまとめて」のような依頼で自動的に読み込まれる。

## 対象

| 対象 | 対象外 |
|---|---|
| Design doc・設計書・ADR の本文・PR 本文・Issue・提案書・報告書・調査結果・議事録・README・手順書・発表資料の原稿 | AI 向けの指示文書（CLAUDE.md / AGENTS.md / SKILL.md / プロンプト）、会話中の返答 |

## モード

- **新規作成**: 読み手と目的を 1 行で決め、会話・Issue・diff にある素材だけから、結論を先頭に置いた文書を書く。書いた後に「この節がなくても読み手は目的を果たせるか」で削る
- **書き直し**: 既存文書を診断し、先頭へ移す結論・表にまとめる代替案・削る節を一覧で示す。承認を得てから上書きし、変更前後の行数・文字数・見出し数を報告する。決定・数値・手順は残し、元の文書にない主張は足さない

## 常に使うには

自動で読み込まれるかどうかは、スキルの説明文と依頼内容の一致で決まる。確実に使いたい場合は、グローバルの指示ファイル（`~/.claude/CLAUDE.md` や `AGENTS.md`）に次の 1 行を足す:

```
人間が読む文書（設計書・PR 本文・報告書・議事録・手順書など）を書く・書き直すときは human-facing-doc-writing スキルを使う
```

## 他のスキルとの関係

- `tech-doc-structuring`: frontmatter・見出しの標準化・ADR の採番など文書の形式を担う。このスキルは中身の取捨選択を担う
- `software-architect`: 設計内容そのものを考える
- `smart-pr`: PR の作成・更新を担う。PR 本文の中身にこのスキルの決まりを使える

## 前提条件

特になし（git リポジトリであることも不要）。
