# Human-facing Doc Writing

人間が読む文書を、読み手が短時間で「この文書から何を持ち帰ればよいか」をつかめる形にする。網羅的な説明書ではなく、読み手の目的に効く情報だけを、結論から順に並べた文書にする。

## 1. 読み手と目的を決める

書き始める前に次の 1 行を決め、以降の取捨選択はすべてこの 1 行で判断する。

`読み手: <誰が> / 目的: <この文書で何を決める・理解する・実行するか>`

この行は文書には書かず、文書を渡すときの返答に添える（想定違いをユーザーが直せるように）。

## 2. 素材を集める

会話・Issue・diff・既存の文書から、決めたこと・その理由・比べて捨てた案・範囲の境界・検証の結果・未決事項を拾う。自分で設計・判断しながら書くときは、その判断と理由、設計の中で比べて捨てた案も素材になる。

- 文書に書く事実は、この素材にあるものだけにする。素材にない事実が必要なら確認し、確認できなければ `TODO: 未確定` と書く。部品の中身がまるごと素材にないときは、その節を置かず、未決事項に「〜は未定」と 1 行で入れる
- 読み手がすでに持っている情報（Issue の要件・リンク先の文書の内容）は、書き写さずリンクで示す

## 3. 文書の部品と順序

文書は次の部品をこの順で持つ。（ ）付きの部品は、条件を満たすときだけ置く。種類ごとの具体形: [references/doc-shapes.md](references/doc-shapes.md)

1. **タイトル**: 何についての文書かが分かる名前
2. **結論**: タイトル（と frontmatter）の直後に 3 文以内（箇条書きなら 3 項目以内）。決定を伝える文書は「採用したもの＋理由」、報告は「結果＋次の行動」、手順書は「この手順で何ができるか＋前提」。関連リンク（Issue・Design doc）は結論の直後に 1 行でまとめる
3. **本文**: 結論を支える順に、判断の中身と根拠を書く。検討の経緯は時系列で再生せず、決まったことだけを書く
4. **検討した代替案**（比べて捨てた案があるとき。自分で設計したなら、設計で選んだ箇所ごとに比べた案がある）: 2 列の表 `| 案 | 採らなかった理由 |`。採用した案は結論にあるので表に入れない。理由は 1 行
5. **やらないこと**（Design doc では置く。ほかの文書では、読み手が範囲内と思いそうな境界があるとき）: 依頼の隣にあるが扱わないものを箇条書きで
6. **未決事項**（あるとき）: 誰に何を確認するか、答えが変わったときの影響
7. **検証・リスク**（あるとき）: 実行した検証とその結果。リスクはこの設計に固有で、対策が決まっているもの

用語は、1 の「読み手」が知らない語だけを、初めて出てくる文の中で短く補う。

プロジェクトや呼び出し元にテンプレート（PR テンプレート・社内の設計書の型など）があるときは、その見出しを使い、各節の中身をこの部品の考え方で最小にする。見出しの順序が決まっていて結論を先頭に置けないときは、タイトルを結論の文にする（例: 「ADR-0003: セッションの保存先に Redis を採用する」）。

## 4. 表現

| こう書かない | こう書く |
|---|---|
| 〜することができます / 〜することが可能です | 〜できる、〜する |
| 〜が挙げられます / 〜と考えられます | 言い切る |
| 〜を行う | 〜する |
| 「可読性が向上する」「保守性が高まる」だけの利点 | 何がどう良くなるかを 1 つ具体的に |
| 同じ主張を別の節でもう一度 | 1 か所にまとめ、ほかの節からはリンクする |
| 冒頭の「本ドキュメントでは〜を説明します」、末尾の「まとめ」 | 削除する（結論が冒頭にある） |
| It is worth noting that / In order to / leverage | 削除する / To / use |

## 5. 仕上げ（書いた後に必ず行う）

各節・各段落について「これがなくても、読み手は目的を果たせるか」を問い、果たせるなら削る。そのうえで次を確かめる。

- [ ] 結論がタイトルの直後 3 文以内にある
- [ ] 代替案は 2 列の表になっている（比べた案がなければ節ごとない）
- [ ] 3 章の部品にない節（背景・目的・対象読者・用語・まとめ・今後の拡張性など）を置いていない
- [ ] 同じ主張が 2 か所に出てこない
- [ ] 素材にない事実（案・数値・テスト結果・範囲の境界）を足していない

## 既存の文書を書き直すとき

1. 全文を読み、行数・文字数・見出し数を測る（`wc -l -m`・`grep -c '^#'`）
2. 3 章の部品と 5 章のチェックに照らして、先頭へ移す結論・表にまとめる代替案・削る節とその理由を一覧にする
3. 一覧を示し、承認を得てから上書きする（AskUserQuestion。使えない環境ではテキストで確認する）
4. 書き直す。決定・理由・数値・制約・手順・未決事項は残す。元の文書にない主張は足さない。結論が元の文書のどこにもなければ、作らずに「結論が書かれていない」と報告する
5. 変更前後の行数・文字数・見出し数と、削った節の一覧を報告する

## 保存先

ユーザーの指定がなければ、同じ種類の文書が置かれている場所に保存し、パスを示す。PR 本文・Issue 本文は、ファイルの指定がなければ返答に出す。
